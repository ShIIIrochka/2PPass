**[НАЗВАНИЕ ПРОЕКТА]**

"2PPass - self-hosted корпоративный менеджер паролей"


**[ ПРОБЛЕМНОЕ ПОЛЕ ]**

1. **Ненадёжное хранение и передача паролей**
      * Сотрудники хранят пароли в Google Sheets, Excel, Telegram, др. мессенджерах.
      * Отсутствие единого места для хранения чувствительных данных.
      * Передача паролей вручную или в небезопасных каналах — риск утечки.

2. **Сложности в управлении доступами**

      * Нет централизованной системы контроля прав (кто к чему имеет доступ).
      * Новичкам сложно получить нужные доступы, а уволенным — их вовремя закрыть.
      * Админы тратят время на ручную выдачу/отзыв паролей.

3. **Низкая автоматизация и неэффективный workflow**

      * Нет группировки пользователей и разграничения по ролям.
      * Пароли не синхронизируются между членами команды
      * Нет логов действий (кто что менял, когда и зачем).

4. **Зависимость от внешних (облачных) сервисов**

      * Компании боятся утечек через SaaS-решения.
      * Отсутствие контроля над аптаймом сервиса.


**[ ЗАКАЗЧИК / ПОТЕНЦИАЛЬНАЯ АУДИТОРИЯ ]**
* Малые и средние компании с повышенными требованиями к безопасности
* Крупные корпорации, которые не хотят передавать доступ в облачные сервисы
* DevOps и IT-команды, которым нужен особый контроль над чувствительными данными внутри инфраструктуры

**[ ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ ]**
1. Хранение паролей
      * Возможность создавать записи с полями: логин, пароль, URL, заметка, теги
      * Настройка категорий / групп / папок для паролей
      * История изменений (версионность) записи
      * Удаление и восстановление записей (корзина)

2. Генерация паролей
      * Генератор паролей с настройками (длина, символы, исключения, шаблоны)

3. Управление пользователями
      * Распределение пользователей по ролям: администратор, менеджер, участник
      * Группировка пользователей (отделы, команды)
      * Настройка прав доступа к паролям/папкам на уровне пользователя и группы

4. Шеринг паролей
      * Шеринг паролей с отдельными пользователями или группами
      * Настройка прав доступа: просмотр / редактирование / только временный доступ
      * Аудит доступа: кто и когда получил доступ к какому паролю

5. Аудит и журнал действий
      * Логирование операций: вход, выход, создание, изменение, удаление


**[ ПОХОЖИЕ / АНАЛОГИЧНЫЕ ПРОДУКТЫ ]**
Анализ 3 программных продуктов, которые максимально приближены к заданному функционалу, показал, что:
* LastPass: не является self-hosted решением, что может быть менее безопасно для корпораций, имеет ограниченные возможности для кастомизации групп пользователей и распределения прав доступа.

* Bitwarden: ограничен в области аудита и логгирования действий.

* KeePass: не имеет встроенных функций для совместного использования паролей между пользователями и требует дополнительных усилий для настройки группового доступа и управления правами, что может усложнить его использование в корпоративной среде.
